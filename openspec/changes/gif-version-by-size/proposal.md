## Why

Часть GIF из поиска не отправляется: в строке статуса «Файл больше 8 МБ» (issue #39). Версия для отправки выбирается
по имени, а не по весу: у KLIPY — полный `gif` (по запросу «ган вест» 8–17 МБ у половины выдачи), у GIPHY — `original`,
если нет `downsized`. Скачивание обрывается на защитном лимите 8 МБ, и пользователь не может отправить GIF, который
видит в ленте. Обе выдачи отдают вес у каждой версии, поэтому выбирать можно по нему.

## What Changes

- Версия GIF для отправки выбирается по весу из ответа API: самая тяжёлая из версий не больше 2 МБ — она уходит как
  есть, без конвертации.
- Если версии не больше 2 МБ нет, берётся самая лёгкая из версий не больше 8 МБ; на отправке она пережимается штатной
  конвертацией до 2 МБ (сторона до 512 px, анимация до 4 с и 100 кадров — как у своих стикеров); на последней стороне
  лестницы результат уходит как есть, даже тяжелее 2 МБ.
- Скачанная GIF из поиска тяжелее 2 МБ на отправке тоже пережимается — в том числе из выдачи без весов и из недавних
  GIF, сохранённых до правки.
- У KLIPY запрашиваются промежуточные версии (`mediumgif`, `nanogif`) — между 13-мегабайтным `gif` и `tinygif`
  появляется выбор.
- Выдача без весов в ответе выбирает версию по прежнему порядку имён.
- Лимит скачивания 8 МБ остаётся защитой памяти страницы amo; ошибка «Файл больше 8 МБ» остаётся только для GIF, у
  которой все версии тяжелее лимита.

## Impact

- `src/core/sources/gifs.ts`, `gifs.types.ts` — вес версии в гардах, выбор версии по весу, `media_filter` KLIPY.
- `src/core/app.ts` — пережатие скачанной GIF тяжелее 2 МБ перед отправкой; лимит скачивания переезжает к сетевой
  политике, чтобы источники GIF знали его.
- `src/core/net.ts` — общий лимит скачивания GIF из поиска.
- `tests/gifs.test.ts` — выбор версии по весу, выдача без весов.
- Время отправки: GIF без версии до 2 МБ (редкость — у KLIPY почти всегда есть `tinygif`, у GIPHY — `downsized`)
  отправляется после конвертации, секунды вместо мгновения.
- Схема IndexedDB и формат `RemoteGif` не меняются; версия — патч.
