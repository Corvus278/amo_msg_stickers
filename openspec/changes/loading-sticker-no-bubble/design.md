## Context

Стиль своих сообщений — чистый CSS: `injectMessageStyle()` (`src/core/amoDom.ts`) кладёт в `document.head` один
`<style>`, селекторы которого узнают сообщение по `img[alt*="amostk."]` на пути корень → ряд → пузырь → обёртка
содержимого → медиа ленты. Размер стикера задаёт сброс inline-размера контейнера (`width` / `height: auto`) и лимит
208 px у `img`.

Снимок DOM в живом `web.dev.amo.tm` (отправитель и получатель одного чата; обычная, замедленная сеть и кэш amo):

- **Заглушка.** Пока файл скачивается, `img` в сообщении нет, в том числе при повторном открытии чата, когда файл
  уже в кэше amo (0,1–0,2 с; первое открытие — 0,6–3 с). Разметка медиа (хэши CSS-модулей убраны):

  ```html
  <button class="… photo_media_container-* photo_media_container_with_preview-* …">
    <div class="relative z-0 flex size-full … overflow-hidden" style="width: 420px; height: 210px;">
      <div class="absolute z-30 flex size-full items-center justify-center bg-gray-260">
        <div class="size-4.5 absolute …"><div class="loader-* …">…</div></div>
      </div>
    </div>
    <div class="absolute -inset-1 -z-20"><div class="size-full bg-black-0"></div></div>
  </button>
  ```

- **После загрузки** слой с заливкой и спиннером сменяется `<img alt="<имя файла>" …>`, сплошной блок подложки —
  `<canvas>`. Контейнер с inline-размером — тот же элемент, размер у него тот же. Промежуточных состояний нет.
- **Отличий нашего стикера от обычного GIF в заглушке нет**, кроме inline-размера: ни имени файла, ни `title`,
  `aria-*` или `data-*`.
- **Размер заглушки** — натуральный размер картинки, вписанный в 420 px без увеличения (512×256 → 420×210,
  128×128 → 128×128); он известен amo из данных сообщения до скачивания файла.
- `id` корня `message+<uuid>` стабилен между загрузками и одинаков у отправителя и получателя.

Средствами расширения заглушку не узнать (proposal.md, «Why»), поэтому часть правки — в amo.

## Goals / Non-Goals

**Goals:**

- Контракт с amo, который закрывает и распознавание, и размер заглушки, и не знает о стикерах: amo помечает любую
  картинку медиа ленты, а что с этим делать — решает наш CSS.
- Один `<style>`, как сейчас: без JS-слежения за лентой и без правки узлов amo.
- Правка amo stickers работает с amo и без контракта; без него поведение прежнее.

**Non-Goals:**

- Мерцание после отправки при закрытии панели вложений — отдельная задача.
- Свой индикатор загрузки вместо спиннера amo.
- Узнавать заглушку без правки amo (память `id` сообщений и т. п.) — см. «Decisions».

## Decisions

### Контракт: имя и размер на контейнере картинки

amo кладёт на контейнер картинки — элемент с inline-размером, родитель будущего `img` — атрибут `data-file-name` с
именем файла (тем же, что в `alt`) и CSS-переменные `--media-w` / `--media-h` с размером самого контейнера — теми же
числами, что в его inline `width` / `height`, без единиц:

```html
<div class="…" style="width: 420px; height: 210px; --media-w: 420; --media-h: 210"
     data-file-name="wide.amostk.k-sticker.gif">
```

И в заглушке, и после загрузки: контейнер один и тот же, и признак не пропадает в момент смены.

- На контейнере, а не на кнопке медиа: он один живёт в обоих состояниях рядом с `img`, а переменные наследуются
  внутрь.
- Размер — переменными, а не `data-*`: `var()` в `calc()` работает во всех браузерах, где идёт amo stickers, включая
  Safari. Числа из `data-*` читает только типизированный `attr()`, которого в Safari нет.
- Числа нужны, потому что inline `width` / `height` amo из CSS не прочитать, а вписать блок в 208 с сохранением
  пропорций можно только по числам.
- Размер контейнера, а не натуральный размер картинки: amo уже вписал натуральный размер в свой предел (420, у
  пересылки 392) без увеличения, а вписать в предел и потом в 208 — то же, что сразу в 208 (512×256 → 420×210 →
  208×104; 128×128 остаётся 128×128). amo не нужно доставать натуральный размер отдельно — переменные дублируют уже
  посчитанные значения.

Отвергнуто: запоминать `id` сообщений, в которых уже видели наш `alt`, и генерировать CSS по `[id="message+…"]` —
первое появление сообщения на устройстве всё равно в пузыре, нужен журнал в IndexedDB и слежение за лентой.
Отвергнуто: заглушка стикера — всегда квадрат 208 — скачок у вытянутых и маленьких стикеров.

### Распознавание: `alt` или метка контейнера

Наш контейнер картинки — `[class*="photo_media_container-"] > div`, у которого `data-file-name` содержит `amostk.`
или прямой ребёнок — `img[alt*="amostk."]`; стикер — то же с `.k-sticker.`. Все `:has()` пузыря, хвоста, строки
автора, подложки и сброса размеров кнопки медиа держатся за этот контейнер вместо `img`. Путь до медиа и исключения
ответа, пересылки и «Избранного» не меняются.

### Размер заглушки стикера — из переменных

Для контейнера стикера с `data-file-name`:

```css
width:  min(calc(var(--media-w) * 1px), calc(208px * var(--media-w) / max(var(--media-w), var(--media-h)))) !important;
height: min(calc(var(--media-h) * 1px), calc(208px * var(--media-h) / max(var(--media-w), var(--media-h)))) !important;
```

— вписать в 208 без увеличения; `!important` — только против inline-стиля amo. Загруженный `img` в таком контейнере
с лимитом 208 даёт тот же размер, поэтому появление картинки ничего не сдвигает. Контейнер без `data-file-name`
сохраняет нынешний сброс в `auto` (`:not([data-file-name])`), и размер задаёт загруженный `img`.

Правило выбрано атрибутом, а не наличием переменных: контракт кладёт их вместе, а «невалидна в момент вычисления»
у `var()` без значения дала бы `unset` неявно — по атрибуту видно, какая ветка сработала.

### Заливка и подложка заглушки

- Слой заливки со спиннером — ребёнок контейнера, отличный от `img` (`> :not(img)`): у стикера фон убирается,
  спиннер остаётся. Структура, а не класс цвета, — amo может сменить цвет в теме. У GIF заливка остаётся: он
  непрозрачный и после загрузки занимает ту же площадь.
- Подложка — соседний элемент после контейнера в кнопке медиа (`контейнер ~ div`): сплошной блок в заглушке и
  `canvas` после загрузки скрываются одним правилом у всех наших сообщений.

### Стенд

Мок «Отправить» в `dev/harness.html` кладёт сообщение с разметкой заглушки из снимка и через паузу меняет слой
заливки на `img`, а блок подложки — на `canvas`. Переключатели: «долгая загрузка» (пауза в несколько секунд) и «amo
без метки» (контейнер без `data-file-name` и переменных — прежнее поведение).

### PR в amo web

Атрибут и переменные ставит компонент, который рисует контейнер картинки медиа ленты: имя файла у него есть до
скачивания, а размер он уже пишет в inline-стиль. Ставятся на любую картинку, без проверки маркера: amo не знает о стикерах. PR и релиз —
по процессу репозитория amo; правка amo stickers от него не зависит и мержится раньше.

## Risks / Trade-offs

- [amo не примет PR или выпустит его позже] → без контракта поведение прежнее, правка amo stickers ничего не ломает.
- [amo переименует атрибут или переменные] → контракт записан в спеке `chat-message-style` и в PR amo; селекторы — в
  одном `amoDom.ts`.
- [Имя `--media-w` пересечётся с переменной amo] → перед PR проверить поиском по CSS amo; при конфликте имя меняется
  в обоих PR до мержа.
- [Размер из данных сообщения, по которому amo считает контейнер, не совпадёт с размером файла] → на стенде и в живом amo сравнить размер
  заглушки и загруженного стикера по сценарию «Загрузка без скачка».
- [Спиннер без заливки плохо виден на фоне чата] → проверка в обеих темах; если не читается — вернуть заливку у
  стикера через `/opsx:update`.

## Migration Plan

amo stickers: стиль применяется после перезагрузки страницы amo; откат — предыдущая версия. amo web: изменение
аддитивное (атрибут и переменные), откат — ревёрт PR; amo stickers при этом возвращается к прежнему поведению сам.
