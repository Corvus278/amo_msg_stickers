## Why

(issue #48)

При открытии чата, пока файл стикера скачивается, amo показывает на его месте серую заглушку со спиннером — в
пузыре и в размере обычного фото (до 420 px по стороне). Через 0,1–3 с картинка загружается, и сообщение прыгает:
пузырь пропадает, стикер сжимается до 208 px. Заглушка есть при любом открытии чата, даже когда файл уже в кэше amo.

Причина — в заглушке нет `<img>`, а с ним и `alt` с именем файла: по разметке наш стикер не отличить от обычного GIF,
кроме inline-размера. Стиль amo stickers узнаёт сообщение только по `alt` и до загрузки картинки не срабатывает.
Средствами расширения это не исправить, поэтому нужна правка на стороне amo.

Вторая проблема — хрупкость. Поле ввода и сообщение amo stickers находит по tailwind-классам, хэшам CSS-модулей,
`aria-label` и пути `[id^="message+"] > div > div > div > …`. Любая правка вёрстки amo ломает их молча: в новой
версии amo web (линия `perf-master`, выкатывается на тестовый стенд s1) у хвоста пузыря уже нет класса
`message_tail-`.

## What Changes

- **amo web** (amo-messenger/web#13, MR в `perf-master`): ключевые блоки ленты и поля ввода несут стабильные
  `data-*` атрибуты (`data-feed-*`, `data-compose-*`), состояния — отдельными атрибутами (`data-outgoing`,
  `data-with-reply`, `data-visible` …). Контейнер картинки — `data-photo-frame` с именем файла `data-file-name` и
  своим размером в CSS-переменных `--media-w` / `--media-h`, и в заглушке, и после загрузки.
- **amo stickers — две разметки.** Знание о DOM amo разделено на две реализации одного контракта: стабильная — по
  `data-*` атрибутам новой amo, прежняя — по классам и структуре нынешней amo. Ядро получает элементы через фасад
  `amoDom.ts` и не знает, какая разметка на странице. Разметки не пересекаются: прежняя не трогает узлы со
  стабильным маркером.
- **Заглушка в стабильной разметке.** Сообщение узнаётся по `data-file-name` контейнера ещё до загрузки картинки:
  без пузыря, хвоста и подложки; заглушка стикера — сразу в итоговом размере (вписан в 208×208 CSS px, без
  увеличения), без серой заливки, со спиннером amo. Загрузка картинки не меняет размер и положение стикера.
- **Прежняя разметка** — поведение как сейчас: заглушка в пузыре, после загрузки — стикер без пузыря.
- Стенд `dev/harness.html`: переключатель разметки amo (прежняя / стабильная) и заглушка загрузки картинки.

## Capabilities

### New Capabilities

— нет.

### Modified Capabilities

- `chat-message-style`: распознавание своего сообщения — и по имени файла на контейнере картинки в стабильной
  разметке; новое требование к сообщению, картинка которого ещё загружается; работа в обеих разметках amo.
- `composer-integration`: поле ввода и кнопка эмодзи находятся в обеих разметках amo.

## Impact

- `src/core/amoDom*.ts` — фасад, две разметки, общий построитель стиля ленты; знание о DOM amo остаётся только в
  них. `app.ts` и `sender.ts` не меняют вызовов.
- `dev/harness.html` — переключатель разметки и состояние загрузки картинки.
- amo web — MR amo-messenger/web#13 в `perf-master`; без него стабильная разметка просто не находится на странице.
- Версия amo stickers — патч (`0.17.0` → `0.17.1`).
- Отправка, имя файла и пикер не меняются. Мерцание при закрытии панели вложений после отправки — отдельная задача.
