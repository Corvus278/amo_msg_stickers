## Context

Пикер — Preact-дерево в closed shadow root за фасадом `createPicker` (`open` / `close` / `setTheme`). Панель смонтирована всегда, закрытая скрыта `display: none`. Представление — `View` из пяти видов (`recent`, `gifs`, `pack`, `add`, `settings`), переключается `switchTo` из `usePickerView`. Паки открываются по одному: `PackView` читает стикеры одного пака, недавние — одна смешанная выборка до 40 записей (`db.ts`: `pushRecent`, `listRecent`). GIF-лента раскладывается `splitColumns` в две flex-колонки (#33), вся выдача лежит в DOM.

Открытие — клик по кнопке в `app.ts` (`toggle`), закрытие — повторный клик, Escape или `mousedown` вне кнопки. Попап эмодзи amo открывается наведением: 250 мс до открытия, 250 + 250 мс до закрытия, закрытие — анимация 200 мс.

Ограничения: `target: chrome120`, CSS пикера — Tailwind 3 строкой в shadow root, зависимости не добавляем без нужды, всё про DOM amo — только в `amoDom.ts`.

## Goals / Non-Goals

**Goals:**
- Состояние пикера из трёх частей: режим, экран поверх режима, запрос прокрутки к разделу.
- Виртуализация обеих лент без измерения ячеек: геометрия считается из ширины ленты и известных размеров элементов.
- Логика наведения, раскладок и окна виртуализации — чистые функции и контроллеры без DOM, покрытые юнит-тестами.

**Non-Goals:**
- Поиск стикеров по эмодзи (#32).
- Координация с попапом эмодзи amo: он живёт своими таймерами, и короткое перекрытие двух попапов при переходе курсора от эмодзи к стикерам допускается.
- Изменение схемы IndexedDB: версия базы остаётся 1.
- Перетаскивание стикеров между паками, порядок паков, избранное.

## Decisions

### Состояние: режим, экран, якорь

`View` заменяется тремя полями контекста `usePickerView`:

```
mode:   'stickers' | 'gifs'           -- нижний переключатель
screen: null | 'add' | 'settings'     -- вложенный экран поверх режима
anchor: { sectionId, seq } | null     -- запрос прокрутки ленты стикеров к разделу
```

Методы: `setMode`, `openScreen`, `closeScreen`, `scrollToSection(sectionId)` (заодно `mode = 'stickers'`, `screen = null`). `seq` растёт на каждый запрос: повторный клик по той же вкладке снова прокручивает к разделу. Импорт и сохранение своего стикера зовут `scrollToSection` вместо `switchTo({ kind: 'pack' })`.

Оба режима смонтированы всегда: неактивный скрыт, у каждого своя сохранённая прокрутка, которая восстанавливается при показе, — у скрытого `display: none` прокрутка теряется. Экраны «Добавить» и «Настройки» лежат оверлеем поверх режима, а режим под ними остаётся в раскладке: прокрутка и запрос поиска переживают возврат «Назад» без восстановления. Под оверлеем режим получает `inert`.

Последний режим пишется в `localStorage` страницы amo под ключом `amo-stickers:mode` на каждое переключение и читается при первом открытии попапа на странице. Нет значения, значение не из `'stickers' | 'gifs'` или доступ к хранилищу бросает (запрет хранилища, приватный режим) — режим выбирается по библиотеке: `countStickers() > 0` → «Стикеры», иначе «GIF». Чтение и запись — в чистом модуле с хранилищем параметром (`readMode(storage)` / `writeMode(storage, mode)`), чтобы тест гонял его без браузера; каждое обращение в `try/catch`.

*Альтернатива:* хранить режим в настройках `Host` (`chrome.storage.local`, хранилище менеджера userscript-ов). Отклонено: режим — удобство интерфейса, а не настройка; запись на каждое переключение гоняла бы сообщение в service worker или `GM_setValue`, а `getSettings` асинхронен и задержал бы первый рендер режима. Режим не секрет, поэтому то, что `localStorage` читают скрипты amo, не мешает.

### Виртуализация на фиксированной геометрии

Лента стикеров — плоский список рядов двух видов: заголовок раздела (32 px) и ряд ячеек. Ширина панели фиксирована (352 px), ширина ленты снимается один раз `ResizeObserver`-ом: так учитывается полоса прокрутки на Windows. Из неё — сторона ячейки: `(width − gap·(COLUMNS − 1)) / COLUMNS`, 5 колонок, зазор 4 px (на macOS — ровно 64 px). Высоты рядов известны без рендера, поэтому:

```
buildStickerLayout(sections, width) -> { rows: [{ kind, sectionId, top, height, items }], sectionTops, total }
visibleRows(rows, scrollTop, viewport, overscan) -> [from, to)   -- бинпоиск по top
activeSection(sectionTops, scrollTop) -> sectionId                -- бинпоиск
```

Рендер — контейнер высотой `total`, в нём абсолютно позиционированные ряды из окна `[from, to)`, запас — по одной высоте окна сверху и снизу. `scroll` пересчитывает окно в `requestAnimationFrame`, не чаще кадра.

GIF-лента — та же схема. `splitColumns` возвращает позиции: колонка, `top`, `height` ячейки — теперь в пикселях, с зазором, потому что ширина колонки известна. Ячейки лежат в DOM в порядке выдачи и позиционируются абсолютно: порядок Tab совпадает с порядком выдачи, а не идёт колонками, как после #33. Окно — элементы, пересекающие видимую область с запасом: линейный фильтр по сотням элементов укладывается в микросекунды, бинпоиск по колонкам не нужен. Раздел недавних GIF — та же раскладка над трендами, заголовки разделов — строки высотой 32 px в общей геометрии.

*Альтернатива:* `@tanstack/virtual-core`. Отклонено: при фиксированных высотах своя реализация — несколько чистых функций, а библиотека добавит вес бандла и измерение, которое здесь не нужно.

*Альтернатива:* `content-visibility: auto` на разделах. Отклонено: элементы остаются в DOM, `<img>` с GIF продолжают декодироваться и анимироваться, а спека требует, чтобы GIF вне экрана не проигрывались.

### Данные ленты стикеров

Одно чтение на открытие: `listAllStickers()` — `getAll` по хранилищу стикеров, группировка по `packId` и сортировка по `createdAt`. Записи держат ссылки на блобы, а не их содержимое, поэтому чтение всей библиотеки дешёвое. Object URL создаётся только для ячеек в окне (`urlOf` при рендере ячейки), кэш `useObjectUrls` отзывается при закрытии попапа, как сейчас. Декодирование уходит вместе с размонтированным `<img>`.

### Недавние по видам

Вид — производная от `SendItem.kind`: `local` → стикер, `remote` → GIF. Схема хранилища не меняется: `pushRecent` обрезает до 40 только записи своего вида, `listRecent(kind)` фильтрует, `clearRecent(kind)` удаляет вид целиком. Смешанные записи прежней версии распределяются по видам без миграции — у каждой вид уже записан. Ключи записей (`l:…`, `r:…`) не меняются.

### Наведение и закрепление

Контроллер без DOM `createHoverPopup({ openDelay: 250, closeDelay: 500, onOpen, onClose, isHeld })` с событиями `enter`, `leave`, `click`, `dismiss` и таймерами через переданный планировщик — тестируется на фейковых таймерах vitest. `app.ts` вешает `mouseenter` / `mouseleave` на обёртку кнопки: хост попапа лежит внутри неё, поэтому курсор над попапом тоже внутри обёртки, и события из shadow root ретаргетятся на хост. Клик — `click` (закрепить или закрыть), `mousedown` вне обёртки и Escape — `dismiss`.

`isHeld` спрашивается в момент срабатывания таймера закрытия, а не подписывается на изменения: фасад отдаёт `picker.isHeld`, провайдер пишет в общий объект удержания четыре причины — фокус в текстовом поле (`focusin` / `focusout` панели по `input` и `textarea`), открытый диалог файла (`click` по `input[type=file]` до его `change` или `cancel` — `cancel` у файлового поля есть с Chrome 113), идущий импорт, идущая конвертация. Удержание не мешает `dismiss`: клик вне попапа и Escape закрывают его всегда.

`openedBy: 'hover' | 'click'` уходит в `open()`: `useSearchFocus` ставит фокус в поиск GIF только при открытии кликом и при переключении в режим «GIF» кликом.

### Анимация закрытия

Закрытие — состояние `closing` на 200 мс: панель получает класс ухода (`opacity-0 translate-y-[5px]`, `pointer-events-none`), по `transitionend` или таймеру фасад переводит её в `display: none`. Повторное открытие во время `closing` отменяет таймер и снимает класс ухода.

*Альтернатива:* `transition-behavior: allow-discrete` на `display`. Отклонено: утилиты для него в Tailwind 3 нет, а анимировать уход `display` нужно в паре с `@starting-style` для обеих фаз, и поведение хуже видно в коде, чем явное состояние.

### Меню: контекстное и раздела

Один компонент `Menu`: позиция — от точки клика или прямоугольника кнопки, в пределах панели; фокус на первый пункт, стрелки, Escape и клик вне закрывают меню и возвращают фокус на источник, `keydown` не всплывает до обработчика Escape панели. Контекстное меню ячейки открывается событием `contextmenu`: его шлёт и правый клик, и клавиша меню, и `Shift+F10`. Подтверждение удаления пака и очистки недавних — существующий `useConfirmPress` на пункте меню и кнопке заголовка.

### Статичные обложки паков

`createImageBitmap(blob)` для GIF декодирует первый кадр. Обложка рисуется в `<canvas>` вкладки, битмап кэшируется по id стикера и закрывается при закрытии попапа. Без `<img>` у обложки нет анимации и не держится декодер на каждую вкладку.

### Статус, заглушки, фокус, прокрутка

- Статус — абсолютный слой над футером; live region смонтирована всегда, как сейчас.
- Заглушки GIF — элементы раскладки с `kind: 'skeleton'` и средними пропорциями: восемь при первой загрузке, по одной в конец каждой колонки при подгрузке. Заглушки стикеров — ряды пустых ячеек, пока идёт `listAllStickers`.
- Прогресс отправки — оверлей со спиннером в ячейке по `isBusy` из `useCellSend`.
- Фокус — `focus-visible:ring-*` на ячейках, вкладках, кнопках режимов и пунктах меню.
- Прокрутка — `scrollbar-gutter: stable` и прозрачный `scrollbar-color`, который становится видимым при наведении на ленту: ширина ленты не меняется.

### Порядок работы

Сначала чистые модули с тестами (недавние по видам, раскладки и окно, контроллер наведения), затем каркас состояния и панели, затем режимы, затем состояния и полировка. Старые `Tabs/`, `Tab/`, `RecentView/`, `PackView/`, `StickerGrid/` удаляются, когда их заменители подключены: пикер остаётся рабочим после каждой группы задач.

## Risks / Trade-offs

- [Высоты рядов расходятся с реальной вёрсткой (шрифт заголовка, полоса прокрутки)] → высоты — константы в одном модуле, классы рядов задают `height` явно, а ширина ленты снимается `ResizeObserver`-ом; стенд проверяет Windows-полосу эмуляцией `scrollbar-gutter`.
- [Перекрытие с попапом эмодзи при переходе курсора от эмодзи к стикерам, около 0,5 с] → принято (Non-Goals); наш попап позже в DOM и перекрывает попап эмодзи.
- [`mouseleave` не приходит, если курсор ушёл за окно браузера] → закрытие по `leave` у `document` через `mouseout` с `relatedTarget === null`; открытый файловый диалог держит попап через `isHeld`.
- [Первое открытие читает всю библиотеку] → записи без блобов; при 2 400 стикерах чтение — единицы-десятки миллисекунд, запасной план — чтение по пакам в порядке ленты.
- [Переход с `View` ломает места, которые переключают вкладки (импорт, сохранение, удаление пака)] → все вызовы `switchTo` перечислены в задачах и заменяются явными методами.

## Migration Plan

Данные не мигрируют: хранилища и ключи те же, недавние делятся по виду на чтении. Откат — предыдущая версия расширения или userscript, база совместима в обе стороны; после отката недавние снова показываются общим списком.
