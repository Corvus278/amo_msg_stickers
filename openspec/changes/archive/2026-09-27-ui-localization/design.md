## Context

Мотивация — в proposal.md. Что известно об amo web (по исходникам и поведению страницы):

- i18next, языки `ru` и `en`, запасной — `ru`, списка поддерживаемых языков нет: браузер `de-DE` получает русские
  тексты. Язык берётся только из `navigator.languages` (первый элемент), detector кэширует его в `localStorage`
  страницы под ключом `i18nextLng` как есть (`ru-RU`, `en-US`, `de-DE`). Смены языка без перезагрузки нет, пункт
  «Язык» в настройках amo не подключён.
- `<html lang>` в amo всегда `ru` — по нему язык не узнать. Наружу (`window`) язык не выставлен. Desktop-клиент язык
  странице не передаёт: `navigator.languages` там — язык ОС.
- Селекторы `amoDom.ts` от языка не зависят: `aria-label="Send message"` и `"cancel edit"` в amo — литералы, не
  ключи перевода; `aria-placeholder` переводится, но мы проверяем только его наличие.

У нас: около 80 строк интерфейса по-русски литералами в компонентах `src/core/ui/Picker/**`, в `app.ts` и
в текстах ошибок ядра (`sender.ts`, `convert.ts`, `tgs.ts`, `net.ts`, `sources/*`), адаптерах userscript
(`gmNetwork.ts`). Ошибка из service worker расширения приходит в content script строкой (`FetchResponse.error`) —
SW живёт вне страницы amo и её `localStorage` не видит. Название пака «Мои стикеры» записано в IndexedDB при создании
(`ensureCustomPack`) и из записи показывается во вкладке, заголовке и буквами обложки (`coverLetters`).

## Goals / Non-Goals

**Goals:**

- Один источник языка на страницу, чистая функция выбора с юнит-тестом.
- Полнота перевода проверяется компилятором: ключа без английского варианта быть не может.
- Параметры подстановки типизированы: вызов без нужного параметра — ошибка `tsc`.
- Ядро не знает, в каком окружении запущено: язык читается так же в расширении и в userscript.

**Non-Goals:**

- Библиотека i18n (i18next, lingui и т. п.): два языка, ~80 строк, без множественных форм — зависимость и её вес в
  бандле content script и userscript не окупаются.
- Множественные формы: сейчас ни одна строка не зависит от числа. Появится такая — `Intl.PluralRules` в том же модуле.
- Перевод логов консоли (`console.warn`) и ошибок-инвариантов разработчика («usePicker вызван вне PickerProvider»,
  «Невалидный параметр имени файла», «Неизвестный формат ответа» в SW): их видит только разработчик.

## Decisions

### Язык: `localStorage.i18nextLng`, затем `navigator.languages`

`resolveLocale(stored, languages)` — чистая функция: первый непустой из `stored` и `languages[0]`, основной тег до
`-`/`_` в нижнем регистре; `en` → `'en'`, иначе `'ru'`. `readAmoLocale()` — обёртка над окружением: чтение
`localStorage.getItem('i18nextLng')` в `try/catch` (хранилище может бросать) и `navigator.languages`, с фолбэком на
`navigator.language`.

`localStorage` страницы доступен и content script расширения, и userscript в изолированном мире — это одно
хранилище origin. `i18nextLng` первым — потому что это то, что amo применила: если amo подключит пункт «Язык» в
настройках (i18next пишет выбор в тот же ключ), мы пойдём за ним без правок. Сейчас значения совпадают с
`navigator.languages[0]`, и фолбэк даёт тот же ответ, если amo ещё не успела записать ключ (скрипт стартует на
`document_idle`, amo инициализирует i18n раньше).

Альтернативы: `<html lang>` — у amo всегда `ru`; язык по тексту DOM amo (перевод `aria-placeholder`) — хрупко и
завязано на конкретную строку; `chrome.i18n.getUILanguage()` — язык интерфейса браузера, а не amo, и его нет в
userscript.

### Словари — модули TS, русский — эталон типов

```
src/core/i18n/
  locale.ts            resolveLocale, readAmoLocale, AMO_LOCALE_KEY = 'i18nextLng'
  messages.ru.ts       export const RU = { 'picker.title': 'Стикеры и GIF', … } as const satisfies Record<string, string>
  messages.en.ts       export const EN: Messages = { … }
  translate.ts         setLocale, getLocale, t(key, params), LocalizedError
  i18n.types.ts        Locale = 'ru' | 'en', MessageKey, Messages, MessageParams<K>
```

- `MessageKey = keyof typeof RU`, `Messages = Record<MessageKey, string>` — `EN` без ключа или с лишним ключом не
  компилируется.
- Подстановки — `{name}` в строке. `MessageParams<K>` выводит имена из литерального типа строки `RU[K]`
  (template literal type), и `t('status.packAdded')` без `{ title }` — ошибка типов. Совпадение набора подстановок в
  `EN` с `RU` проверяет юнит-тест (типом строки `EN` не литеральные).
- Ключи — по месту в интерфейсе, с точкой: `footer.settings`, `gifs.nothingFound`, `error.send.draftNotEmpty`. Фраза —
  целиком одним ключом: «Отправить стикер «{caption}»» — один ключ, а не «Отправить» + имя ячейки. Склейка
  переведённых кусков ломает порядок слов и падежи в другом языке.
- Текст с элементом внутри (ссылка в подсказках «Настроек»: «Бесплатно на {link}», «Создайте любого бота в {link}.
  Токен хранится локально.») — тот же ключ с подстановкой `{link}`, а компонент собирает узлы маленьким
  `renderMessage(key, { link: <ExternalLink …/> })` в `ui/`: строки делятся по подстановкам, в `{link}` встаёт узел.
  Раскладка на «до» и «после ссылки» двумя ключами навязала бы английскому русский порядок слов.

Альтернатива — JSON-файлы: теряется проверка полноты и типов подстановок компилятором, а загружать их лениво не
из чего — userscript один файл.

### Язык — состояние модуля, выставляется в `start()`

`setLocale(readAmoLocale())` — первая строка `start(host)`, до `injectMessageStyle` и создания кнопок и пикера.
`t()` читает текущий язык модуля. Язык не меняется до перезагрузки страницы (спека `localization`), поэтому
подписки, контекста Preact и перерисовки на смену языка нет. По умолчанию язык модуля — `'ru'`: тесты, которые
проверяют русские тексты, не требуют настройки, а тест английского ставит язык явно и возвращает в `afterEach`.

Альтернатива — контекст Preact с языком: не дотягивается до ядра вне UI (`sender.ts`, `net.ts`, `convert.ts`),
пришлось бы протаскивать язык параметром через всю конвертацию и сеть.

### Ошибки: текст при создании, ключ — через границу service worker

- В мире страницы (content script, userscript) ошибка получает текст на языке amo в момент создания:
  `new SendError(t('error.send.draftNotEmpty'))`, `new Error(t('error.telegram.badLink'))`. `errorMessage` не
  меняется.
- Ошибки, которые может создать service worker, — сетевой политики и лимита из `core/net.ts` — `LocalizedError`:
  `Error` с полями `key` и `params`, текст — `t(key, params)` на языке своего мира. SW при отказе кладёт в
  `FetchResponse` кроме `error` ещё `key` и `params`, если ошибка — `LocalizedError`; `content.ts` при наличии `key`
  создаёт `LocalizedError` заново — уже в мире страницы, на языке amo. Прочие ошибки SW (сообщение браузера
  `Failed to fetch`, `HTTP 403 <тело>`) идут текстом как есть: `httpError` от языка не зависит — `HTTP <код>` и
  тело ответа.
- В userscript сеть работает в мире страницы, и `gmNetwork.ts` берёт тексты из `t()` напрямую; `BODY_NOT_BYTES`,
  `NETWORK_ERROR` и соседние константы становятся ключами словаря.

Альтернатива — передавать язык в каждом сообщении content → SW: SW общий для вкладок, пришлось бы протаскивать
язык через все функции `net.ts` параметром, а ключ ошибки и так нужен для диагностики.

### «Мои стикеры» — по id пака, без миграции

`packTitle(pack)` в `ui/Picker/`: для `CUSTOM_PACK_ID` — `t('pack.custom')`, иначе `pack.title`. Им пользуются
`feedSections` (вкладка, заголовок раздела), `PackCover` (буквы обложки своего пака), подписи меню пака и статус
импорта. Поле `title` в записи `custom` остаётся как есть (русское у старых баз, у новых — на языке создания) и в
интерфейсе не показывается. Миграция IndexedDB не нужна, схема не меняется.

Альтернатива — переписывать `title` записи при старте на язык интерфейса: запись в базу на каждое открытие страницы
ради подписи, и гонка между вкладками с разными языками.

### Язык поиска GIF

- GIPHY: `lang=<ru|en>` в `search` GIF и стикеров. У `trending` параметра языка в API нет — тренды GIPHY общие.
- KLIPY (API Tenor v2): `locale=ru_RU` / `en_US` в `search` и `featured`.
- Язык — аргумент функций источника из `useGifFeed` (`getLocale()` в момент запроса), а не глобальное чтение внутри
  `sources/gifs.ts`: тест проверяет параметры запроса для обоих языков без подмены модуля.
- Ключ кэша выдачи язык не включает: он не меняется в пределах страницы. Недавние GIF хранят ссылки и от языка не
  зависят.

### Метаданные сборок

- `manifest.json`: `"default_locale": "ru"`, `"description": "__MSG_extDescription__"`, название литералом
  «amo stickers». Переводы — `src/extension/_locales/{ru,en}/messages.json`; `build.mjs` копирует каталог в
  `dist/extension/_locales/` (`cpSync` рядом с записью manifest), и zip релиза и PR, который пакует
  `dist/extension/` целиком, получает их без правок CI. `default_locale` — `ru`, как запасной язык amo: браузер на
  немецком показывает русское описание, как amo показывает русский интерфейс.
- Userscript: `// @description` (русский, по умолчанию) и `// @description:en` в `USERSCRIPT_BANNER`; `@name` один.
  Tampermonkey и Violentmonkey выбирают `@description:<язык>` по языку браузера.

### Глоссарий

Термины, у которых есть перевод в amo web, берутся из его словарей; остальные — по интерфейсу Telegram.

| ru | en | откуда |

| Отправить | Send | amo `translation.json` `send` |
| Настройки | Settings | amo `conversations.json` `settings` |
| Поиск GIF | Search GIFs | amo `search` = Search |
| Удалить | Delete | amo `delete` |
| Стикеры / GIF (режимы) | Stickers / GIFs | Telegram |
| Недавние | Recent | Telegram |
| Тренды | Trending | Telegram |
| Мои стикеры | My stickers | — |

| Создать стикер | Create sticker | — |

Английские строки — без типографики русского: кавычки “…”, без неразрывных пробелов. Русские строки не меняются.

## Risks / Trade-offs

- [amo поменяет способ хранения языка (ключ, формат)] → фолбэк на `navigator.languages` даёт тот же язык, что
  выбирает amo сейчас; при расхождении пикер будет на языке браузера, а не упадёт.
- [KLIPY не учитывает `locale`] → выдача остаётся рабочей (спека `gif-search`); проверка в живом запросе на шаге
  проверки, при игноре параметр остаётся — вреда нет.
- [Новая строка интерфейса литералом мимо словаря] → проверка в задачах: `rg` по кириллице вне комментариев в
  `src/` пуст, кроме словаря `RU` и инвариантов; правило в `CLAUDE.md`.
- [Английский текст длиннее русского ломает раскладку (чипы источников, кнопки футера, «Сохранить в …»)] →
  проверка на стенде в английском языке, обе темы.
- [Язык в SW по умолчанию `ru`: ошибка SW без `key` на русском] → все тексты, которые SW создаёт сам, — ошибки
  `net.ts`, и они `LocalizedError`; остальное — сообщения браузера и HTTP без перевода.

## Migration Plan

Миграции данных нет. Выкатывается минорной версией; откат — прошлая версия, записи IndexedDB и настройки
совместимы в обе стороны.
