## Context

`src/extension/manifest.json` без поля `key`. `build.mjs` читает manifest, добавляет dev-адреса в `matches` только в
`pnpm watch` и пишет результат в `dist/extension/manifest.json` — остальные поля копируются как есть. Карточка в
Chrome Web Store создана первой загрузкой пакета без `key` (с ключом стор первую загрузку отклоняет), панель выдала
публичный ключ; ID карточки — `abjnjphijggkkdbbmkldhibgepgdcgip`.

## Goals / Non-Goals

**Goals:**
- ID распакованного архива равен ID из стора, в том числе в `pnpm watch`.
- Случайная замена ключа ловится тестом, а не жалобами на пропавшие настройки.

**Non-Goals:**
- Ссылки на стор в доке и README, раздел «Обновление» — после одобрения карточки.
- Автопубликация в стор из релиза — issue #52.

## Decisions

**Ключ — строкой в `manifest.json`, без переноса в `build.mjs`.** Поле статично и нужно в обеих сборках (боевой и
`pnpm watch`), а `build.mjs` меняет manifest только там, где сборки различаются. Альтернатива — подставлять ключ при
сборке из переменной окружения — ничего не прячет: ключ публичный и так лежит в каждом архиве релиза.

**Ключ — только тот, что выдал CWS.** Свой ключ сгенерировать можно, но стор примет лишь пакет со своим ключом, и ID
архива и стора разошлись бы навсегда. Формат — base64 DER (SubjectPublicKeyInfo) одной строкой, без заголовков PEM.

**Тест считает ID из ключа по алгоритму Chrome** — SHA-256 от DER, первые 16 байт, каждая шестнадцатеричная цифра
`0–f` переводится в букву `a–p` — и сверяет с ID карточки. Сравнивать строку ключа целиком было бы проще, но тест по ID
проверяет и то, что строка — валидный ключ (иначе Chrome откажется грузить расширение), и то, что это ключ именно нашей
карточки. Проверка валидности — разбором DER как публичного ключа средствами `node:crypto`.

## Risks / Trade-offs

- [У тех, кто ставил архив без ключа, ID меняется] → однократно; ключи и токен вводятся заново, стикеры и паки
  остаются (IndexedDB на домене amo). Предупреждение — в теле PR, откуда берутся заметки релиза.
- [Chrome при загрузке распакованного расширения с ID уже установленного может потребовать удалить старое] → сценарий
  «Распаковка в другую папку сохраняет настройки» проверяется вручную в Chrome до мержа; если Chrome так не умеет,
  сценарий уточняется по факту.
- [Две копии с одним ID — из стора и распакованная — в одном профиле невозможны] → ожидаемо: это одно расширение.
