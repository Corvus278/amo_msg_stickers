## MODIFIED Requirements

### Requirement: Браузерное расширение
Система SHALL поставляться как Chrome MV3-расширение, которое запускается на страницах `https://*.amo.tm/*`, `http://localhost:3000/*` и `http://127.0.0.1:3000/*`. Расширение MUST запрашивать только разрешение `storage` и доступ к хостам GIPHY, KLIPY и Telegram API. Manifest расширения MUST нести публичный ключ карточки Chrome Web Store, поэтому ID расширения SHALL быть одним и тем же — `abjnjphijggkkdbbmkldhibgepgdcgip` — при установке из Chrome Web Store и при загрузке распакованного архива из любой папки. На тех же страницах расширение MUST подключать агент в мире страницы (требование «Агент в мире страницы»).

#### Scenario: Установка распакованного расширения
- **WHEN** пользователь загружает `dist/extension` как распакованное расширение и открывает web.amo.tm
- **THEN** в поле ввода появляется кнопка стикеров, в консоли страницы строка `[amo-stickers] started (extension)`

#### Scenario: ID архива совпадает с ID из стора
- **WHEN** пользователь загружает распакованный архив из релиза на странице расширений браузера
- **THEN** у расширения ID `abjnjphijggkkdbbmkldhibgepgdcgip` — тот же, что у версии из Chrome Web Store

#### Scenario: Распаковка в другую папку сохраняет настройки
- **WHEN** пользователь сохранил ключ GIPHY и, не удаляя расширение из браузера, загрузил архив новой версии из другой папки
- **THEN** ID расширения не меняется, и в «Настройках» стоит сохранённый ранее ключ GIPHY

#### Scenario: Агент расширения
- **WHEN** расширение установлено и открыт чат amo
- **THEN** стикер уходит через очередь amo, а в списке разрешений расширения нет новых пунктов

### Requirement: Userscript
Система SHALL поставляться как самодостаточный userscript (`dist/amo-stickers.user.js`) с тем же поведением, что и расширение. Он работает в менеджерах userscript-ов (Tampermonkey и т. п.). В менеджере, который это поддерживает, userscript MUST выполняться в изолированном мире, а не в мире страницы: скрипты страницы MUST NOT получать доступ к коду ядра, к API менеджера и к настройкам. В мир страницы MUST попадать только агент (требование «Агент в мире страницы»). Если скрипт подключён на страницу без менеджера и API менеджера недоступно, userscript MUST работать через прямой `fetch` со страницы и `localStorage`. Повторное подключение скрипта на той же странице MUST NOT создавать второй экземпляр ни ядра, ни агента.

#### Scenario: Запуск в менеджере userscript-ов
- **WHEN** пользователь устанавливает скрипт в Tampermonkey и открывает web.amo.tm
- **THEN** в поле ввода появляется кнопка стикеров, в консоли строка `[amo-stickers] started (userscript)`

#### Scenario: Изоляция от страницы
- **WHEN** скрипт страницы amo обращается к `GM_xmlhttpRequest`, `GM_getValue` или к глобальным объектам userscript
- **THEN** они для него не определены

#### Scenario: Подключение без менеджера
- **WHEN** `dist/amo-stickers.user.js` подключён на страницу напрямую, без менеджера userscript-ов
- **THEN** кнопка стикеров появляется, сетевые запросы идут прямым `fetch` со страницы, настройки хранятся в `localStorage`

#### Scenario: Двойное подключение
- **WHEN** скрипт подключён на странице дважды
- **THEN** у каждого поля ввода по-прежнему одна кнопка стикеров, один клик по стикеру отправляет одно сообщение

#### Scenario: Отправка через очередь в менеджерах
- **WHEN** userscript установлен в Tampermonkey или Violentmonkey, в поле ввода набран текст, и пользователь кликает на стикер
- **THEN** стикер уходит через очередь amo, текст в поле остаётся

#### Scenario: Агент не выполнился
- **WHEN** агент не выполнился в мире страницы (менеджер или политика страницы не пустили его)
- **THEN** стикер при пустом поле уходит запасным путём, вставкой в поле

## ADDED Requirements

### Requirement: Агент в мире страницы
Внутренний путь отправки amo доступен только скриптам страницы, поэтому в мире страницы SHALL выполняться агент, который
умеет одно: отправить переданный ему файл отдельным сообщением в открытый чат amo. Агент MUST NOT отдавать странице и
вызывающей стороне ничего, кроме статуса команды и причины отказа: ни код ядра, ни API менеджера, ни настройки, ни
содержимое поля ввода. Команды агенту видны скриптам страницы; через агента страница MUST NOT получать возможностей
сверх тех, что у неё уже есть, — отправить файл в открытый чат она может и сама.

#### Scenario: Посторонняя команда
- **WHEN** скрипт страницы шлёт агенту команду в неверном формате
- **THEN** агент ничего не отправляет и не отвечает

#### Scenario: Ответ не раскрывает черновик
- **WHEN** агент отправил стикер при тексте в поле ввода
- **THEN** в его ответах нет текста поля, вложений и настроек — только статус
