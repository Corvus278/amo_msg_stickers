## Why

Импорт пака из видеостикеров (например, `video_gachi`: 45 стикеров VP9 512×~390 до 3 с) роняет вкладку amo по
памяти уже на ~4-м стикере (issue #8). Конвертация держит все RGBA-кадры стикера в памяти (до ~141 МБ `ImageData`),
при весе больше 2 МБ перекодирует весь набор ещё трижды (384, 320, 256 px) синхронно на главном потоке (19–44 с на
стикер), а `<video>`, отвалившийся по таймауту, не освобождается — живых видео копится до семи. Причина в устройстве
конвейера, а не в скорости JS, поэтому лечится архитектурой конвертации.

## What Changes

- Конвертация становится потоковой: кадр кодируется в GIF сразу после захвата, его RGBA выбрасывается. Набор кадров
  стикера целиком в памяти больше не держится ни на одном шаге.
- Размер результата (512 / 384 / 320 / 256 px) выбирается **до** полного прохода — по оценке веса на пробных кадрах.
  Если итог всё же не уложился в 2 МБ, следующий меньший размер снимается новым проходом по источнику, а не
  масштабированием сохранённых кадров.
- Квантизация, дизеринг и LZW уходят в Web Worker, запущенный из встроенного в бандл кода через blob URL. Там, где
  Worker не запускается, кодирование идёт на главном потоке с уступкой потока между кадрами.
- Главный поток занят захватом кадра (seek, `drawImage`, подпись) и не блокируется дольше ~1 с подряд.
- Worker получает кадры с обратным давлением: захват не уходит вперёд кодирования больше чем на пару кадров.
- `<video>` освобождается (`removeAttribute('src')` + `load()`) при любом исходе: успех, ошибка, таймаут; ожидание
  события не оставляет висящих слушателей и сразу падает по `error` элемента.
- Потоковый конвейер общий для видео, `.tgs` и анимированных картинок (`ImageDecoder`).
- Сборка получает отдельный бандл Worker-а, который вшивается в `content.js` и `amo-stickers.user.js` строкой.

Вне задачи: уменьшение веса GIF (18 из 45 стикеров `video_gachi` не укладываются в 2 МБ и при 256 px — остаются
тяжелее лимита, как и сейчас), lossy LZW, межкадровая дельта, WebAssembly.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `sticker-conversion`: требование «Размер и вес» — размер выбирается по оценке веса до полного прохода, повторный
  проход идёт по источнику; новое требование к ресурсам конвертации — пик памяти, блокировка главного потока,
  освобождение `<video>`.

## Impact

- `src/core/convert.ts`, `src/core/convert.types.ts` — источники кадров, выбор размера, потоковое кодирование.
- Новые модули ядра: чистый потоковый кодировщик GIF (общий для Worker-а и фолбэка), оценка веса и выбор размера,
  точка входа Worker-а и его запуск через blob URL.
- `build.mjs` — esbuild-плагин, собирающий Worker отдельно и отдающий его код строкой; `src/types.d.ts` — описание
  такого импорта.
- `src/core/sources/telegram.ts`, `src/core/ui/Picker/useStickerDraft/` — API `toStickerGif` сохраняется, правок не
  ожидается.
- Тесты: кодировщик, оценка и выбор размера — юнит-тестами в `node`; захват кадров, Worker и память — на стенде
  `dev/harness.html` и в живом amo.
- Зависимости не добавляются. Версия — минор (`0.5.0`).
