## Why

Проверки сейчас живут только в pre-commit (`.husky/pre-commit`): их можно обойти `--no-verify`, а vitest там гоняется
лишь по изменённым файлам. Правило «каждый PR поднимает версию в трёх местах» держится на внимательности автора. Сборку
для установки каждый собирает у себя: готового архива расширения, который можно скачать и поставить, нет.

## What Changes

- GitHub Actions на каждый PR в `master`: отдельные проверки линта (eslint + prettier), типов, тестов и сборки. Упавшая
  проверка видна в PR.
- Проверка версии в PR: `package.json`, `src/extension/manifest.json` и `@version` в `build.mjs` совпадают, версия
  строго выше, чем в `master`.
- Сборка PR выкладывается артефактом прогона — архив расширения можно поставить руками до мержа.
- Релиз после мержа в `master`: те же проверки, затем тег `v<версия>` и GitHub Release с архивом расширения
  (`amo-stickers-<версия>.zip`, `manifest.json` в корне архива) и userscript-ом (`amo-stickers.user.js`); заметки —
  автогенерация GitHub по PR.
- Повторный прогон релиза на уже выпущенной версии не падает и нового релиза не создаёт.
- Версия поднимается до `0.3.0` (минор, по правилу репозитория) — первый релиз выйдет из этого PR.
- Документация: раздел о CI и релизах в `CLAUDE.md`, установка из релиза в `README.md`.

Не входит: публикация в Chrome Web Store, автообновление userscript (`@updateURL`/`@downloadURL`), настройка
защиты ветки `master` (делается руками в настройках репозитория, см. tasks).

## Capabilities

### New Capabilities

- `ci-cd`: проверки PR (линт, типы, тесты, сборка, версия) и выпуск релиза с архивом расширения и userscript-ом после
  мержа в `master`.

### Modified Capabilities

(нет)

## Impact

- Новые файлы: `.github/workflows/*.yml`, общий шаг установки окружения, проверка версии в `scripts/` (чистый модуль + обёртка) и её
  юнит-тесты в `tests/`; `tsconfig.json` — `scripts` в `include`.
- `package.json`, `src/extension/manifest.json`, `build.mjs` — только номер версии.
- `CLAUDE.md`, `README.md` — документация.
- Репозиторий GitHub: у workflow релиза право `contents: write` (теги и релизы через `GITHUB_TOKEN`), секреты не
  нужны.
- Код расширения (`src/`) не меняется.
