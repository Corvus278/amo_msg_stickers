# user-docs Specification

## Purpose
Дока пользователя amo stickers: сайт, по которому человек без опыта ставит расширение или userscript в свой браузер,
получает ключи GIF и токен бота и импортирует пак из Telegram; а README — вход, который ведёт на неё.

## Requirements

### Requirement: Сайт доки
Дока SHALL публиковаться сайтом на GitHub Pages по адресу `https://mcar2107.github.io/amo_msg_stickers/`, собранным из
исходников в Markdown в репозитории. Изменение исходников доки в `master` MUST публиковаться без выпуска релиза. Язык
доки — русский; адреса страниц MUST оставлять место второму языку без смены адресов русских страниц. У сайта MUST быть
навигация по разделам, поиск по тексту и светлая и тёмная тема.

#### Scenario: Правка доки
- **WHEN** в `master` попадает коммит, меняющий только исходники доки
- **THEN** сайт доки обновляется, новый релиз не создаётся

#### Scenario: Битая ссылка
- **WHEN** страница доки ссылается на несуществующую страницу доки
- **THEN** сборка сайта падает с указанием ссылки

### Requirement: Разделы доки
Дока SHALL содержать разделы: главная (что это и выбор способа установки), установка, ключи GIF, импорт из Telegram,
обновление, частые вопросы, политика конфиденциальности. Шаги со сторонним интерфейсом (страница расширений, менеджер
userscript-ов, @BotFather, Telegram, панели KLIPY и GIPHY, Safari) и экраны amo stickers MUST сопровождаться скринами;
на главной MUST быть демо-видео отправки стикера. Личные данные на скринах (чужие имена, списки чатов, ключи, токены)
MUST быть скрыты. Место под скрин, которого ещё нет, MUST быть отмечено в исходниках и MUST NOT ломать сборку сайта.

#### Scenario: Скрина ещё нет
- **WHEN** место под скрин отмечено, а файла скрина в репозитории нет
- **THEN** сайт собирается, на странице нет битой картинки

#### Scenario: Демо на главной
- **WHEN** пользователь открывает главную доки
- **THEN** под описанием играет по кругу видео без звука: открытие панели стикеров и отправка стикера и GIF

### Requirement: Адреса страниц браузера
Адрес, который страница сайта открыть не может (`chrome://extensions`, `edge://extensions`, `browser://extensions` и
подобные), SHALL копироваться в буфер по клику, с отметкой «Скопировано» рядом. Без доступа к буферу отметка MUST NOT
появляться, адрес MUST оставаться видимым текстом, который можно выделить.

#### Scenario: Скопировать адрес страницы расширений
- **WHEN** пользователь нажимает `chrome://extensions` в таблице адресов на странице установки для Chromium
- **THEN** адрес в буфере обмена, рядом на полторы секунды появляется «Скопировано»

### Requirement: Установка по окружениям
Раздел установки SHALL начинаться со страницы выбора окружения: браузер на Chromium (Chrome, Яндекс Браузер, Edge,
Opera, Brave, Vivaldi), Firefox, Safari, десктоп-приложение amo. Главная доки MUST вести на эту страницу. Для браузеров
на Chromium MUST быть три равноправных способа на вкладках: «Chrome Web Store» (рекомендуемый), «Архив», «Userscript».
Пока расширения нет в Chrome Web Store, вкладка MUST говорить об этом и вести к двум другим способам. Для Firefox MUST
описываться установка userscript, для Safari — userscript через приложение Userscripts. Раздел десктоп-приложения MUST
говорить, что способ пока недоступен.

- **Архив:** скачивание последней версии по прямой ссылке, установка распакованного расширения в режиме разработчика.
  Обновление — очистка папки расширения, распаковка новой версии в ту же папку и «Обновить» в списке расширений
  браузера. MUST быть предупреждение, что архив не обновляется сам, а распаковка в другую папку сбрасывает ключи и
  токен.
- **Userscript:** установка менеджера, установка скрипта в один клик по ссылке на последний релиз, разрешения,
  которые спросит менеджер. Основной менеджер — Tampermonkey; для Tampermonkey в Chrome MUST быть шаг включения
  пользовательских скриптов в настройках расширения. Violentmonkey и Safari (Userscripts) MUST быть помечены «без
  гарантий»: способ не проверяется. Для Safari MUST быть сказано, что настройки могут храниться в хранилище сайта amo,
  доступном его скриптам.

#### Scenario: Пользователь Яндекс Браузера
- **WHEN** пользователь нажимает «Установить» на главной доки и выбирает «Яндекс Браузер»
- **THEN** он попадает на страницу с вкладками «Chrome Web Store», «Архив», «Userscript»

#### Scenario: Менеджер без гарантий
- **WHEN** пользователь открывает установку для Safari или описание Violentmonkey
- **THEN** рядом со способом сказано, что он не проверяется, и предложен проверенный способ

#### Scenario: Установка userscript в один клик
- **WHEN** пользователь с установленным Tampermonkey нажимает в доке ссылку установки userscript
- **THEN** Tampermonkey открывает окно установки последней версии amo stickers

#### Scenario: Десктоп
- **WHEN** пользователь открывает раздел десктоп-приложения amo
- **THEN** на странице сказано, что способ пока недоступен, и нет инструкций, которые не сработают

### Requirement: Настройка ключей GIF
Раздел ключей GIF SHALL описывать получение ключа KLIPY и ключа GIPHY по шагам — от регистрации до вставки ключа в
«Настройки» amo stickers. KLIPY MUST идти первым и рекомендоваться за выбор контента. Раздел MUST говорить, что у
бесплатных ключей есть лимит запросов — у GIPHY 100 запросов в час, у KLIPY — по данным Partner Panel на момент
написания, — и что его тратят поиск, подгрузка следующей страницы и тренды. Раздел MUST NOT обещать платные или боевые
ключи.

#### Scenario: Упёрся в лимит
- **WHEN** пользователь читает частые вопросы о том, почему поиск GIF перестал работать
- **THEN** он находит объяснение лимита тестового ключа и что делать: подождать или завести ключ второго сервиса

### Requirement: Импорт из Telegram
Раздел импорта SHALL описывать по шагам: создание бота в @BotFather, копирование токена, вставку токена в «Настройки»,
получение ссылки на пак в приложении Telegram и импорт по ней. Раздел MUST предупреждать, что токен — секрет, даёт
управление ботом и хранится только в браузере пользователя.

#### Scenario: Первый импорт
- **WHEN** пользователь без бота проходит раздел импорта по шагам
- **THEN** у него есть токен в «Настройках» и ссылка на пак, импорт стартует

### Requirement: Политика конфиденциальности
Дока SHALL содержать политику конфиденциальности на отдельной странице с постоянным адресом:

- что хранится в браузере: ключи и токен — в хранилище расширения или менеджера userscript, а у userscript без
  хранилища менеджера — в хранилище сайта amo, доступном его скриптам; стикеры, недавние и выбранный режим попапа — в
  хранилище сайта amo;
- какие данные и куда уходят: поисковые запросы и ключ — в GIPHY или KLIPY; токен и имя пака — в Telegram; при
  загрузке GIF и файлов стикеров их серверы получают обычный запрос браузера с IP-адресом; отправленный стикер уходит
  в amo как обычное вложение сообщения;
- что разработчику не уходит ничего.

#### Scenario: Ссылка из карточки стора
- **WHEN** проверяющий стора открывает ссылку на политику конфиденциальности
- **THEN** страница открывается и перечисляет хранимые данные, сторонние сервисы и что разработчику ничего не передаётся

### Requirement: README как вход в доку
README репозитория SHALL начинаться с описания для пользователя: что это, как выглядит, что умеет, — и вести на доку
ссылкой «Установить». Сборка, проверки и устройство для разработчика MUST идти после и не заслонять путь установки.

#### Scenario: Посетитель репозитория
- **WHEN** посетитель открывает страницу репозитория на GitHub
- **THEN** на первом экране README — описание, демо и ссылка на установку, а не команды сборки
